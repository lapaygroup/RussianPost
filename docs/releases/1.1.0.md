# RussianPost SDK 1.1.0 — PHP 7.4

Отдельная линия для **PHP ^7.4 или ^8.0**, сохраняющая прежние конструкторы и поведение API 1.x. Минимум PHP **повышен с >=7.0 в 1.0.2 до 7.4**. Для приложений на PHP 7.0–7.3 этот выпуск не подходит. Основная версия 3.0.0 для PHP ^8.3 использует другую, PSR-18 архитектуру существующих провайдеров.

```sh
composer require lapaygroup/russianpost:^1.1
```

Сохранены прежние классы SDK 1.0.2: тарифный API v2 и параметры доставки, нормализация с ID и iterable-коллекциями, исправление createBatch(null), legacy Tracking single+batch. Новый TrackingApi добавлен отдельно. Optional `Http\HttplugClient` позволяет использовать Guzzle 6.5.8 + guzzle6-adapter 1.1.1 / HTTPlug 1.1.0 без обновления Mailgun 2 / Silex. Мост сохраняет HTTP 4xx/5xx, включая SOAP Fault с HTTP 500, и безопасно переводит транспортные ошибки в PSR-18.

Новый `Providers\TrackingApi` использует отдельный ApiKey и REST single. `TrackingResult` сохраняет неизвестные поля/коды и исходные даты, исключает будущие события из `getOperations()` и принимает явный null групп как пустую историю. Ошибки HTTP/transport/SOAP классифицируются без ключей, тел ответов и цепочек исходных исключений.

Новый SOAP batch включается только через `tracking.batch_enabled=true` и остаётся **экспериментальным**. Реализованы независимые пакеты до 3000 РПО, сохранение уже созданных билетов при частичном сбое и DTO результатов; автоматических retries/polling нет. WSDL и live-контракт ещё не приняты, в публичной документации остаётся противоречие ApiKey/login.

Проверка 15.11.2026 с нашей учётной записью и синтетическим ШПИ: single — HTTP 200 и пустая история, новый batch — HTTP 403/auth, прежний batch — HTTP 200 с SOAP ErrorTypeID=3. Билеты не созданы. Это не свидетельство глобального отключения старого SOAP: другие пользователи сообщают о его работе. `Providers\Tracking` сохранён, автоматического переключения между API нет.

`cashOnDelivery` не подтверждает оплату или выплату; аналога прежних финансовых событий в новом API не подтверждено. Миграция потребителя должна учитывать это отдельно.

Автоматическая проверка: реальный PHP 7.4.33, PHPUnit, PHPStan level 5, Composer strict; CI PHP 7.4/8.1/8.4/8.5. На полном consumer lock прежнего приложения изменились только SDK, http-factory-guzzle 1.1.1 → 1.2.0 и добавился psr/http-client 1.0.3; остальные 60 package records сохранены. Public source/dist install и автономные offline consumer-контракты прошли без path-repositories и локальных симлинков.

Существующие advisories старого HTTP stack не устранены этим выпуском. Исключение blocking в SDK CI относится только к воспроизведению тестового baseline; политика приложения не меняется.
